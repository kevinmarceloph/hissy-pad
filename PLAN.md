## What it is

- One document ("the pad"), a tree of nodes. No days, divisions, inboxes, blocks or time fields. Urgency is position: what matters is near the top, like the Docs inbox today.
- A node is a line of text with optional children. Blank nodes are allowed and act as spacers, the way blank lines do in Docs. Headings are nodes with children ("WL:", "Housey:"); a line can be marked as a header (bold, same size, "#" for a bullet), which is a look, not a structure.
- Done is a strikethrough that stays in place (item 3 in the screenshot stays crossed out where it was), with a × bullet like a bullet journal. "Delete done" removes every crossed-out line in one go; undo is the safety net. (An earlier "sweep under a Done node" idea was dropped 2026-10-28 in favour of deleting.)
- Collapse and expand per node. Links are auto-linked. Plain text otherwise. No formatting, except that any line can be numbered: a run of consecutive numbered siblings counts 1, 2, 3 and a plain line restarts the count, like a Docs list. Pasting "1." lines keeps them numbered. Any line can also be a header: bold at the same size, "#" in place of the bullet; pasting "# " lines keeps them headers and copying writes the marker back. The toolbar's type switcher (· / # / 1.) sets plain, header or numbered; a line is never both. Enter after a header starts a plain line.
- Blank lines are spacers and show no bullet until typed into.
- A first visit on a device opens a short welcome pad (heading with children, a numbered list, a crossed-out line, a spacer) instead of one blank line; the same text is the Paste-in placeholder. If that device then signs in to an account that already has a pad, the untouched sample lines are removed on the first sync and edited ones are kept.
- Paste from Google Docs imports indentation as hierarchy, so the current inbox moves over in one paste. Hissycal's `indentWidth` + `createItemsAfter` already do this for a single day; the same logic ported to the flat model.
- Capture from the phone: share sheet appends to the top of the pad.

- Several pads (added 2026-11-02): "Main" plus any number of named pads, switched from a row of tabs under the title (chips on the phone). A pad is a root-level node with `pad` set; its lines hang under it, so a pad is just a subtree and nothing new syncs. The main pad is the root level itself, as before. Lines move between pads from the toolbar ("Move to…", also on the phone). **Fresh start** (web only): a two-pane view, the pad as it is on the left and what stays on the right; send lines across, name the leftover pad (default "Before 2 Nov 2026"), and one undoable op moves everything left behind into it, order and nesting kept. A line sent across on its own comes up to the top level of its side; a line left behind under a kept parent goes down with the rest.

What it is not: not a calendar, not collaborative. One user, several devices. Pads are a handful of lists, not a notebook of documents.

## Why not just extend Hissycal

Hissycal's model is a nested JSON blob per user, synced by PUT-the-whole-thing with a 409 banner when two devices overlap. That worked for a calendar edited mostly from one device at a time. A scratchpad gets edited from the phone in a queue and the laptop five minutes later, so whole-document conflicts are the normal case, not the edge case. HissyPad flips the model: a flat table of nodes, each row synced on its own, conflicts resolved per node. If it holds up, the Hissycal rewrite starts from this core and adds date and time columns to the same table.

## Data model

One table, `nodes`. Flat, not nested.

| column | type | notes |
|---|---|---|
| id | uuid | generated on the client, so offline inserts need no round trip |
| user_id | uuid | owner, defaults to `auth.uid()` |
| parent_id | uuid or null | null = top level of the pad |
| rank | text | fractional index between siblings, own implementation in `core/rank.ts` with the same integer-plus-fraction shape as the `fractional-indexing` package, so capture at the top stays two or three characters. A move is one row update, never a renumber |
| text | text | plain text, may contain newlines |
| done | boolean | |
| done_at | timestamptz or null | when `done` last flipped on, cleared when it flips off; what "Recently done" sorts by (added 2026-11-02, `20261102010000_nodes_done_at.sql`; the mobile SQLite store adds the column on open). Rows done before the column fall back to `updated_at` |
| collapsed | boolean | synced on purpose: if I fold "Project Ideas" on the laptop I want it folded on the phone too |
| numbered | boolean | shown as "1." within its run of consecutive numbered siblings |
| header | boolean | bold with a "#" bullet; the client never sets it together with numbered (added 2026-10-29, `20261029000000_nodes_header.sql`; the mobile SQLite store adds the column on open) |
| pad | boolean | a root-level row that is a pad of its own; its subtree is that pad's content and the root level stays the main pad (added 2026-11-02, `20261102000000_nodes_pad.sql`). The app edits one pad at a time through a scoped view (`core/pads.ts`: the pad's children lifted to `parent_id = null`), so every op works unchanged inside a pad; the store puts the pad id back on the changed rows before saving |
| updated_at | timestamptz | set by the client that made the change, see sync |
| deleted_at | timestamptz or null | tombstone; rows are never hard-deleted by clients. One `remove` call stamps every row it touches with the same value, which is how the Trash panel groups a delete into one entry (2026-11-02) |

The tree is derived: group by `parent_id`, sort by `rank`, tiebreak by `id`. Every edit is a change to one or more rows. Multi-select drag of five nodes is five rank updates.

Hissycal keeps `expanded` out of the synced document as view state. HissyPad syncs `collapsed` and keeps only selection and scroll position local.

## Sync: offline-first, last write wins per row

The learning item here is "offline-first / local-first sync" from tech-to-learn.md: SQLite on device, change log, idempotent sync, conflict resolution. Hand-rolled, because a single user on three devices is the easy case and the point is to understand it. PowerSync or ElectricSQL is the fallback if it turns into a swamp.

- Every client keeps a full local copy of its nodes (IndexedDB on web, SQLite on mobile) and renders only from that. The app works with no network at all.
- Every local edit stamps `updated_at` with the client's clock plus a small device offset guard (a hybrid logical clock in one line: never emit a timestamp lower than the last one you saw).
- Push: dirty rows are upserted in batches. A `before insert or update` trigger drops any write whose `updated_at` is not newer than the stored row, so last-write-wins is decided on the server and every device converges whatever the arrival order. Replaying a batch is harmless, so retries are free. A row edited while its push is in flight stays dirty.
- Pull: `select * from nodes where synced_at > :cursor order by synced_at`, cursor stored locally. `synced_at` is stamped by the server on every accepted write, so the cursor is not fooled by client clocks; the client also backs the cursor up ten seconds on each pull so a row that committed slightly out of order is still seen (duplicates are harmless, the merge compares `updated_at`). Tombstones come through the same query.
- Live: a Supabase Realtime subscription on `nodes` filtered by `user_id` nudges a pull, so the laptop sees the phone's capture within a second. Realtime is a hint only; correctness comes from the pull cursor.
- Conflicts: the row with the later `updated_at` wins the whole row. Two devices editing the same node's text within the same offline window is the only real loss, and that is rare on a personal pad. Structural conflicts (one device moves a node, the other edits its text) merge cleanly because rank and text are on the same row only when the same device touched both. Orphans (parent deleted on another device) are re-parented to the root on read, never dropped.

The whole engine is pure TypeScript in the core package behind a `LocalStore` interface with about six methods (`getAll`, `upsertMany`, `dirty`, `markClean`, `getCursor`, `setCursor`). Web and mobile each ship one adapter.

## Stack

| layer | choice | why |
|---|---|---|
| repo | pnpm workspaces + Turborepo | the "monorepo with shared TS core" ask on the Expo line of tech-to-learn.md. Hissycal does this with `file:` deps and no task runner |
| `packages/core` | pure TS: types, tree ops, drop resolution, paste importer, sync engine, `LocalStore` interface | no React, no platform APIs, Vitest only |
| `apps/web` | Vite + React 19 + Zustand + vite-plugin-pwa | a SPA, not Next.js: an outliner has no server-rendered page, and Doorstep already covers Next.js. PWA so it installs on the phone before the native app exists |
| `apps/mobile` | Expo (current SDK) + expo-sqlite + Reanimated + Gesture Handler, EAS Build, EAS Update | Hissycal's mobile stack minus the widget modules. EAS Build and EAS Update are the gaps named in tech-to-learn.md |
| backend | Supabase hosted project: Postgres + RLS + Auth (magic link) + Realtime | the most-requested item on the list by a wide margin. No app server at all; the sync engine talks to PostgREST |
| `supabase/` | migrations, RLS policies, pgTAP tests for the policies, seed | run locally with the Supabase CLI, same as Doorstep |
| CI | GitHub Actions: Vitest, Playwright, `supabase db test` | ticks the GitHub Actions line, and this repo has nothing under NDA |
| web hosting | Render static site | static, so no free-tier sleep. Supabase free tier pauses after a week idle; daily use keeps it awake |

Auth is real even though there is one user. RLS is `user_id = (select auth.uid())` on every policy, with the parenthesised form from the Supabase notes so the planner caches it. That makes the schema a worked RLS example for proposals without pretending HissyPad is multi-tenant.

## Editing model

Simpler than Hissycal's Normal/Edit modes. Always editing, like Workflowy, with a selection mode one keypress away.

- One auto-growing `<textarea>` per node. Enter: new sibling below (splits text at the caret). Shift+Enter: newline inside the node. Backspace at the start of an empty node: delete it and move the caret up.
- Tab / Shift+Tab: indent and outdent. Alt+Up / Alt+Down (or Cmd+Shift+Up / Cmd+Shift+Down): move among siblings. Cmd+Enter: toggle done. Cmd+. : collapse and expand.
- Escape: leave the textarea and select the node. Shift+Up/Down extends the selection. Cmd+click toggles, Shift+click ranges. Every keyboard action above works on the selection as a batch. Enter or typing goes back to editing.
- Drag: pointer-based, hand-rolled, no dnd-kit. The pad is a flat list of visible rows, so a drop resolves from pointer y (which gap) and pointer x (which depth, snapped to indent width). That resolver is a pure function in core, `resolveDrop(rows, y, x)`, and both platforms call it. Hissycal's band engine is the same idea with more cases; this one has one list and one axis of depth.
- Mobile: long-press selects, a drag handle on the bullet moves, swipe right marks done. Keyboard shortcuts work with an external keyboard.
- Cross-outs stay visible where they are. "Delete done" removes them all; undo brings them back. Numbered list: Cmd+Shift+7 on a line or a selection.
- Sort (2026-11-17, web): the top bar's "Sort…" deals the pad's top-level lines one card at a time (crossed-out lines and blank spacers are left out). Swipe, arrow keys or buttons: left sends the line to "Later", right to "Today", up to "Today" crossed out, down deletes (2026-11-21: the line and what is under it go to the Trash, and Back or the Trash restores them; before that, down skipped). Skip is still there as a button, and the S key on web, and leaves the line where it is. Either side can point at any pad or Main instead (two selects under the card, remembered per device in the LocalStore meta keys `sort.left` and `sort.right`); the default pads are found by name and made the first time a line is sent to them. Each picker also ends in "New pad…" (2026-11-17), which names and makes a pad on the spot and points that side at it without leaving the sort. The card is live: its text and sub items edit the real rows, and a field at the bottom adds a sub item. A line lands at the bottom of its new pad with its subtree, each send is one undo step, and Back undoes everything since the last card came up. Logic in `packages/state/src/sort.ts`, the card in `apps/web/src/panels/Sort.tsx`. The phone app has the same screen since 2026-11-17 (`apps/mobile/src/ui/Sort.tsx`, a full-screen modal from the top bar's "Sort" until 2026-11-23, since then a view under the top bar and the pad chips, PanResponder and Animated so it ships as an OTA update; targets are picked from an alert). Shipped without a simulator run, at Kevin's call: check it on the phone.
- Ungroup (2026-11-17): a toolbar button next to Fold, web and phone, on when a target has children. Each target's children come out to its own level right after it, in order; the line itself stays and grandchildren keep their parents (`ungroup` in core, one undo step).
- Make pad (2026-11-17): a toolbar button, web and phone, on when the selection comes down to one line. The line becomes a pad at the end of the tabs: its text (flattened to one line, "Untitled pad" when blank) is the name, its subtree the content, and crossed out, numbered, header and folded are dropped (`lineToPad` in core). Only that one row is written. The pad shown stays open; one undo step turns it back.
- Fold into (2026-11-20): the opposite of Make pad, in the pad's own sheet on the web ("Fold in" next to a picker of the other pads) and under "Fold into…" in the pad's menu on the phone. The pad becomes a line at the top of the pad picked (Main included): its name is the text, its lines the sub items (`padToLine` in core). Only that one row is written. If the folded pad was the one shown, the pad it went into opens; one undo step makes it a pad again, in its old place among the tabs.
- Pad counts and the counting rule (2026-11-20): each tab (web) and chip (phone) shows its pad's open top-level lines as a small number, Main included, and nothing at zero (`padCounts` in core; the same list the Sort queue, the widgets and the watch show). One rule for every count the app shows: a line with no text is not counted (`isBlank`, `countLines` in core's `tree.ts`). That covers the selection bar, the Moved / Deleted / Added / Fresh start toasts, Delete pad's confirmation, the folded chip ("…" when only blank lines are under it), a drag's label, the Trash and Done panels' "+N under it" and "Restore all N", and the widgets' and watch's "+N under it" (`Rows.swift`, which needs a new build). A blank top-level line with sub items still counts as one item of its pad.
- Space under a header, and the floating buttons moved (2026-11-20): every header line has one line of empty space under its group (after its last drawn sub item, or after the header itself when it is folded or has none), on web and phone. It is drawn, not stored: `headerGaps` in core says where the spaces go. A tap on it adds a blank last sub item to that header and starts editing it, opening the header if it was folded (`cmdAddUnder`, one undo step). Nested headers that end on the same row each get their own space, innermost first. On the phone the floating buttons sit at the bottom right now, above the toolbar and the keyboard, and the check is a left/right switch: • on the left for open, × on the right for crossed out, with the side the line is on filled; a tap flips it.
- Inline marks (2026-11-20): `**bold**`, `*italic*` or `_italic_`, `__underline__` and `~~strikethrough~~` are detected from a line's text and drawn as such, with the symbols left in and visible. Nothing is stored: `inlineSpans` (core `inline.ts`) turns the text into styled spans each time it is drawn. Stray symbols stay plain by Markdown's flanking rule, a notch stricter: an opening mark touches the word after it and has no letter or digit before it, a closing mark touches the word before it and has no letter or digit after it, so `2 * 3 * 4`, `5*3*2`, `snake_case_name` and `*.txt` are left alone. Marks inside a URL are not marks, a mark never crosses a line break, an unpaired one is just a character, and marks nest (`**a _b_ c**`, `***both***`). The line being edited is plain text on web and phone: the marks show once the caret leaves. Not done: the Trash, Done and Sort screens, the widgets and the watch draw the text plain.
- Sub-pads (2026-11-20): a header line at the top level of a pad (Main included) is a sub-pad. Nothing new is stored: the header flag and the row's place are the whole definition (`isSubPad`, `listSubPads` in core), so making a top-level line a header makes a sub-pad and turning it back unmakes it. A `Place` (`{ padId, subId }`) is now what anything is sent to: a pad, or one of its sub-pads. Move to… lists every place as "Pad → Sub-pad", the sub-pads of the pad shown included, and the lines land at the top of the sub-pad's own lines (`moveToPlace`, `cmdMoveTo`). The same list feeds the Sort screen's two pickers (a side's stored choice can be a sub-pad's row id; a card goes to the bottom of its lines) and Fold into (a pad folds into any place but its own sub-pads). In the tabs (web) and chips (phone), a pad with sub-pads has a chevron beside its name: it lists them with their open-line counts, and picking one opens the pad and scrolls to the header (`openSubPad`, the store's `reveal`). A sub-pad is still drawn as a header inside its pad; there is no zoomed-in view of one. In those lists a sub-pad's name is its first line up to an em dash (`subName`): what follows the dash is a description, shown on the header itself only, so an emoji label can carry a note. A Done is a three-column `PATCH` (`done`, `done_at`, `updated_at`), not the whole row: an edit made to the same line on another device meanwhile is kept, and the server's last-write-wins trigger still drops the Done if the line has a newer `updated_at`. It lists every open line of a pad, not the first 25. Sign-in is a hand-over: the watch cannot share the phone's session (a refresh token works once) and has no keyboard, so when the phone app is open and sees the watch is not on its account, it gets a one-time sign-in token from the `watch-token` Edge Function (`supabase/functions/watch-token`, service role, the caller's own account only, nothing emailed) and passes it over WatchConnectivity; the watch trades it for its own session, kept in its keychain. Signing out on the phone signs the watch out. A watch whose phone app is not signed in still gets the snapshot through the phone, as before. No typing or moving on the watch yet. Checked on a Mac against the local stack (the Swift sync code: sign-in, fetch in pages, Done, a Done held offline, the merge, token refresh, a revoked session, and 60 random outlines against `widgetSnapshot`) and on paired simulators with the phone simulator shut down (lines added elsewhere arrive, a Done reaches the server, a Done made with the server unreachable is held and then sent, the sign-in survives a relaunch, signing out on the phone signs the watch out). Not checked: the background sync, which the simulator does not hand out on demand. `watch-token` is on the hosted project since 2026-11-20 (it answers 401 without a sign-in and 405 to a GET); the hand-over itself on a real phone and watch is not checked yet.
- Adding a line on the watch (2026-11-23): each pad on the watch starts with "New line". It opens the watch's own text entry (dictation, scribble, or the keyboard on watches that have one) and what comes back goes to the top of that pad, where the phone's Add puts it (`cmdAddToPad`). Signed in, the watch makes the row itself: an id, a rank above the pad's first line (`Rank.before` in `Rows.swift`, the `between(null, b)` case of core's `rank.ts`) and an `updated_at` from its clock, sent as an insert that the server ignores if it already has that id (a retry after a lost answer). With no network the line is held with the Dones and sent first, so a line typed and crossed out offline arrives as both. A watch with no account sends `{dir: 'add', pad, text}` to the phone, which puts it in the widget queue. Top-level lines only: no sub items, no editing, no new pads. Checked on a Mac against the local stack (insert in a pad and in Main, a repeated send, typed and crossed out with no server and then sent, a second device reading the same lists). It is native code, so it needs a new build on the phone and watch.
- Today widget and Add control (2026-11-18, iOS): a third piece on the home screen and a change to the second. "Today" is a list widget (small, medium, large): the open top-level lines of the pad the Sort screen's right side sends to ("Today" unless set otherwise; another pad can be picked in Edit Widget), each with a circle that crosses it out in place, the same queued `{dir: 'done'}` the watch sends. Medium and large have a + that opens the app's "Add to …" prompt for that pad. The small Add widget from earlier in the day is gone: "Add to Inbox" is now a Control (iOS 18+), which can sit on the Lock Screen, in Control Center or on the Action button. A control's intent opens the app and runs inside it, so `targets/widget/AddControlIntent.swift` is compiled into both; it leaves `add?pad=inbox` under `widget.open` in the App Group and the app follows it when it comes to the front (`followOpen` in `apps/mobile/src/widget.ts`).

- Siri sends by itself (2026-11-23, iOS): "Add to HissyPad" used to queue its line until the app was next opened, so the line reached the pad and the other devices only then. Now the intent sends it to the server, as the watch does with a line typed on it, and with the watch's own code: `native/SiriSync.swift` keeps a session of its own in the keychain (a refresh token works once, so it cannot share the app's; the app hands it a one-time token from the `watch-token` function, Siri before the watch because the server keeps one such token per account), asks the server for the ranks under the Inbox pad, and posts the row above the first. The line is still queued first and taken out of the queue once the server has it, so nothing is lost if Siri runs out of time: the send gets eight seconds, and signed out, with no Inbox pad yet or with no network, the line stays queued and the app adds it as before. The app gets a sent line with its next sync. Needs a build.
- Trash and Recently done (2026-11-02): two panels from the top bar, on web and mobile. Trash lists tombstones from the last 30 days grouped by the delete that made them (same `deleted_at`), each with a Restore that lifts the tombstone from the row and the descendants that went with it, re-stamped so it syncs; a restored orphan shows at the root. Recently done lists live crossed-out lines by `done_at` with an Undone button. Decided: keep soft delete, no server purge yet (a purge needs a resync guard for devices that were offline past the window).
- Mobile selection: tap a bullet to select, then tap more bullets to add or remove them (no modifier key). The floating toolbar carries every action.

## Hours (added 2026-11-23)

Oras-oras (`../oras`, an hourly self-tracker, still live and untouched) folded in as a mode of HissyPad, opened from the top bar like Sort. What came over: one row per hour with a plan and a deed (words and a category each), the box on a row as its checkbox, the 24-cell strip, the user's own categories and flags (with icons and colored options), recurring plans, a day that can start at any hour, chimes at chosen minutes. Nothing is seeded: the lists start empty. The old app's data was not imported.

Category icons (2026-11-24): a category is an icon and a name (`icon` on `hour_categories`, one emoji or `''`, cleaned by `cleanIcon`, which flags share). Where room is short (an hour's row, the strip's words, a recurring plan's title in a row) it shows as the icon, or as the name when it has none (`categoryShort`); the pickers and the categories screen show both (`categoryName`). Before this the name itself was split at an em dash, Oras-oras's rule (`shortLabel`, removed here; Oras-oras keeps it). The migration moved names written that way over: the part before the dash became the icon when it was short and had no letter or digit in it, the rest became the name, and the row's `updated_at` went up by one so every device takes it. A name whose first part is words stays whole. The hours engine's `PULL_EPOCH` went to 3 with it.

What is new:

- **A line in an hour.** A row of `nodes` has `slot`, `'YYYY-MM-DDTHH'` or null: a calendar day and hour on the wall clock, the same slot an hour's own row is stored under. The toolbar's "Hour…" opens a picker (a day to step through, 24 hours); an open hour in Hours lists its lines, ticks them, takes them out, and takes a new line typed there (it lands at the top of the pad that is open). The line shows its hour as a small chip in the pad.
- **Done and open per hour.** An hour's row shows its lines as done out of all (`1/2`, with a tick in front when every one is done) and says it in words to a screen reader. The count covers every pad; blank lines do not count.

How it is built:

- Logic in `packages/core/src/hours` and `packages/state/src/hours`, screens in a new package, `packages/ui`, written in React Native and drawn on the web by react-native-web. That is Oras-oras's one good idea about layout (one set of screens), taken for the mode that needs nothing from the DOM; the pad's editor stays per app.
- Four tables on the server, as Oras-oras had them (ms `updated_at`, no deletes, last write wins in a trigger shared by the four). On a device the rows are JSON behind a two-call backend.
- A second sync engine for those tables, started by the same sign-in.
